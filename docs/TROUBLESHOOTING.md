# Troubleshooting (players)

## Lock the game to 60 fps

Tomb Raider: Underworld ties physics and camera to the frame rate (variable time step, one physics step per frame). Above 60 fps
boxes, ragdolls and physics puzzles can break, in the base game and even more in the DLC. Lock the game to **60 fps** with one of:

- in-game V-Sync on a 60 Hz display;
- the frame limiter of your GPU driver (NVIDIA Control Panel → *Max Frame Rate*, AMD *Frame Rate Target Control*) or RTSS;
- [dxwrapper](https://github.com/elishacloud/dxwrapper) with `LimitPerFrameFPS = 60`;
- dgVoodoo2 (see below), which also has an `FPSLimit` option.

## "A problem has occured with your display driver"

**Status (21 Oct 2026): probable cause found and fixed in B133 (included in B138), not yet confirmed on a real GPU.** Update to the B138 kit first; if the box is still there, use the workaround and the test below. Original investigation notes (20 Oct):  The box appeared on a player's PC (real GPU, Windows' own Direct3D 9); the game without
the port starts fine on the same PC. The author's test setup runs the game through dgVoodoo2, so the port's graphics data had never
been checked by Windows' native Direct3D 9 runtime.

What we know:
- The game shows this box when any Direct3D object cannot be created (shader, texture, vertex layout, buffer) or the device reset fails.
- Offline checks of B132 against the original PC game data: textures, vertex layouts and the patched exe are within what the original
  PC game already uses. The port's patched exe does not touch any Direct3D code.
- The only difference found: **113 of the 396 pixel shaders generated by the port are longer than 512 instructions** (the longest
  original PC shader has 462). 512 is the minimum that Direct3D 9 guarantees; many GPUs accept more, some may not. This is the main
  suspect, not yet confirmed.
- Those shaders are only in DLC level/object files. If the box shows up **at start-up or in the main menu**, they are not the cause.

### Workaround: dgVoodoo2 (the configuration the port was tested with)

1. Download dgVoodoo2 from the official site: <http://dege.fw.hu/>.
2. From its zip copy `MS\x86\D3D9.dll` into the game folder (next to `tru.exe`).
3. Copy [`tools/native_test/dgvoodoo/dgVoodoo.conf`](../tools/native_test/dgvoodoo/dgVoodoo.conf) next to it.
4. Start the game. To undo, delete `D3D9.dll` and `dgVoodoo.conf` from the game folder.

### Help us fix it: run the native test (2 minutes, changes nothing)

Download `trudlcport-native-test.zip` from the latest release (or the folder [`tools/native_test`](../tools/native_test)), unzip it
anywhere, close the game and double-click `RUN_TEST.bat`. It asks for the game folder, extracts the shaders from your installed
`mods\` (Python, already needed by the installer) and tries to create every shader, vertex layout and texture format of the port on
your GPU. Then send us (GitHub issue) `native_report.txt` and tell us:

1. **when** the box appears: at start-up, in the main menu, when entering the DLC, or after a while in the DLC (where);
2. GPU, Windows version, monitor resolution and refresh rate;
3. whether the dgVoodoo2 workaround makes it go away.

## In italiano (breve)

- **Blocca il gioco a 60 fps** (V-Sync a 60 Hz, limitatore del driver NVIDIA/AMD o RTSS, dxwrapper `LimitPerFrameFPS = 60`):
  sopra i 60 fps fisica e camera si rompono.
- **"A problem has occured with your display driver"**: problema in analisi. Il sospetto principale sono 113 shader del port più
  lunghi di 512 istruzioni. Rimedio subito: dgVoodoo2 (dal sito ufficiale copia `MS\x86\D3D9.dll` accanto a `tru.exe`, più il nostro
  `tools/native_test/dgvoodoo/dgVoodoo.conf`). Per aiutarci: scarica `trudlcport-native-test.zip` dalla release, lancia `RUN_TEST.bat`
  a gioco chiuso e mandaci `native_report.txt`, dicendo quando compare il riquadro e se dgVoodoo lo risolve.
