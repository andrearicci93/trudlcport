# Tomb Raider: Underworld - game knowledge base

What the project learned about the game itself (PC 1.1, Xbox 360 retail and title update, DLC 1 *Beneath the Ashes*, DLC 2 *Lara's Shadow*) from its data and code, written at game level: what happens, under which conditions, with which numbers.
Status: ✅ proven from data / code or seen live · 🔶 inferred · ⬜ open. Where a later finding corrected an earlier one only the corrected fact is listed, marked "(corrected)".
Technical detail (addresses, structs, tools) is in [ENGINE.md](ENGINE.md); the Source column names its section and row, a repo doc, or a `Befund-*` finding report (kept outside this repo, named only).

## 1. Structure

| Topic | Fact | Status | Source |
|---|---|---|---|
| Units | The world is cut into stream units (one `.drm` each). The PC unit list has 119 units: base levels l1-l7 with 23 / 16 / 9 / 11 / 6 / 6 / 13, DLC 1 12, DLC 2 11 | ✅ | ENGINE §4.1 "Unit list" |
| Units without data | `dlc_level1_left` / `_right` and `dlc_level3_start` .. `dlc_level6_start` are listed but exist in no archive on any platform (four never-built DLC slots) | ✅ | ENGINE §4.1 "Units without a DRM" |
| Streaming | Up to 32 units are resident. Stream portals link units; crossing one makes the target the main unit and loads its neighbours (portals with the auto-load flag) | ✅ | ENGINE §4.1, §4.2 |
| Level change | A level change (story end, mission start, death reload) runs on the main thread behind the loading screen; PC loads took 23-38 s (median 32 s). A death reload waits at least 3 s | ✅ live | ENGINE §3 "Level load loop", §4.2 "Reload after death" |
| Look-through portals | A few portals (DLC 1, base `l2_cliffhall_b` <-> `l2_hubhall`) name a unit two rooms away; Lara never walks through them - read as preload / look-through portals | 🔶 | ENGINE §8.2 "DLC 1 level chain (PK.1)" |
| Cells and stream groups | Inside a unit the scene is split into cells; when Lara enters another cell the game loads the stream groups (material / texture sets) that the cell's list names, also from neighbour units | ✅ | ENGINE §16 "Cell stream lists" |
| Sonar maps | Each unit has a separate `<unit>_map.drm` collision mesh used only by the PDA sonar | ✅ | ENGINE §14 "PDA sonar map (ping map) build" |
| Navigation | Enemy paths use the unit's NavPower mesh. Hand-made "custom" areas exist only in DLC 1 (209 areas, mostly facing down or steep = walls / ceilings for spiders 🔶). Units with bats or sharks also carry a 3D graph | ✅ | ENGINE §15 "Data statistics", "3D image (Level+0x68)" |
| Objects | Units place objects as intros; an object loads its children (weapons, dismemberment pieces, companions) after itself | ✅ | ENGINE §5.1 "Object request / load end" |
| Shared ids | For data ids (DTPs, animations, materials) the first loaded copy wins; a later file with the same id uses that copy | ✅ | ENGINE §5.1 "Id tables: first loaded copy wins" |
| Scripts | Object scripts run per instance; their variables are lost on reload unless they are "stickies" (persistent int / bool / float) | ✅ | ENGINE §6.1 "What is saved and what is not" |
| Puzzle objects | Movable puzzle parts are uber objects: a state graph whose transitions fire on time, commands, damage, impacts or joint angles (degrees) / slider positions (units). Multi-part puzzles test the node of linked parts | ✅ | ENGINE §9 "Event / command delivery (Q74)", "Object check cond 9" |
| Triggers | Trigger volumes (box or sphere) send enter / leave / inside events; trigger planes and stream portals are crossing tests. The test point is 200 units above Lara's feet | ✅ | ENGINE §11 "Volume = two points, no sweep (Q73)" |
| Trigger scripts | A trigger volume's "first in" runs once per save (sticky); "in" / "out" run on every crossing | ✅ | ENGINE §11 "Trigger volume base script 3484 (Q73)" |
| Cinematics | A cinematic object plays once (sticky "played"); trigger volumes can preload it before the playing trigger is reached | ✅ | ENGINE §11 "Cinematic base script 3523 (Q73)" |
| Game time | Logic runs in ticks of 1/30 s; one frame is capped at 2 ticks, so below 15 fps the game slows down instead of stepping further | ✅ | ENGINE §11 "Frame time clamp (Q73)" |
| Physics | 405 bodies / 1200 geoms / 300 joints; variable time step, 5 solver iterations; below ~26 fps each frame runs as two half steps | ✅ | ENGINE §13.6 "Physics frame step (Q69)", "MultibodySystem::Step" |
| Scale | About 290 units per metre (280-310; Lara's bind mesh is 511 units tall) (corrected: not 100 per metre) | 🔶 | ENGINE §4.3 |

## 6. PDA, sonar, hints, objectives

| Topic | Fact | Status | Source |
|---|---|---|---|
| Sonar | The ping map casts rays (500 per frame) from Lara's eye (+200 units) to map vertices inside the ping radius; only geometry in range and in line of sight is drawn, plus pingable objects and portals in sight | ✅ static | Befund-Sonar-DLC2-1411; ENGINE §14 |
| Sonar maps DLC 2 | Real maps only in `dlc_yggdrasil_hall01` / `hall02` / `end` (copies of the base Yggdrasil maps); the start unit and all `dlc2_*` rooms carry a developer placeholder mesh spelling "MAP", so the sonar shows almost nothing there | ✅ data / Xbox 🔶 | Befund-Sonar-DLC2-1411 |
| Sonar maps DLC 1 / base | DLC 1 maps are real except `dlc_level1_start` and `dlc_treasureroom` (placeholder); the base game uses the same placeholder in five cinematic / corridor units | ✅ data | Befund-Sonar-DLC2-1411 |
| Sonar memory and limits | The sonar remembers per map point whether a ping revealed it (unknown / revealed / being checked) and keeps that in the save; it draws a face only when all its points are revealed. Opening the PDA loads every connected map room of the floor, but a ping checks only the current room and its direct neighbours. At most about 93 500 map triangles are drawn per frame - larger areas are cut | ✅ static | ENGINE §14 "PDA sonar draw + full-map patch"; Befund-Sonar-Komplett-1411 |
| Sonar floors | Every sonar map carries floor bits; the PDA shows one floor at a time - the lowest floor bit of the room Lara stands in when it opens. It loads the rooms of that floor that are connected through portals plus their direct neighbours of other floors, but draws only the floor's rooms. Helheim: helheim01 floor mask 0x02, helheim02 0x06, helheim03 0x04, helheim_hall01 0x03, helheim_hall02 0x02, Yggdrasil 0x04 / 0x04 / 0x0c / 0x08 - opened in helheim03 the map stops at the doorway to helheim01. A room with a floor-change portal shows a marker; aiming the sonar view at a seen marker offers a button that switches the floor (the other floor loads, rooms off it are dropped) | ✅ data + static; button ⬜ | ENGINE §14 "PDA sonar floors, load scope"; Befund-TruMenu-02249-1411 |
| Sonar triangle budget | The 93 572 triangles per frame are only a counter, not a buffer size: the map is sent in batches of 2000 into a vertex pool that grows on PC. Past the budget the rest is dropped in drawing order - the current room first, then the rooms by portal steps, inside a room in file order (so a cut room shows scattered pieces), and every marker / icon drawn after the map. In the DLC 1 water-wheel area the full floor (about 121 600 triangles) loses 23 % - the end of the water tunnel and all of the caverns | ✅ static + live count | ENGINE §14 "PDA sonar floors, load scope" |
| Sonar map sizes, DLC 1 water-wheel area | Opened at the water wheel, the PDA loads 9 map rooms; normally it draws the 5 of Lara's floor (121 667 triangles). All 9 together are 250 909 triangles: water wheel 18 649, pillory 53 190, caverns hall 16 688, water tunnel 13 728, dungeon hall A 32 628, dungeon hall B 40 050, caverns 19 412, dungeon 56 464 and the DLC 1 start room 100 (only the "MAP" placeholder). The pillory and the dungeon alone are bigger than half the game's per-frame budget. Floors: water wheel and caverns hall floor 2, caverns 1+2, pillory 2+3, water tunnel 2+4, dungeon halls 3+4, dungeon 4, start room 5 | ✅ live (TruMenu 0.22.49 log, 2026-11-14) | ENGINE §14 "PDA sonar floors, load scope" |
| Sonar on the Xbox | The Xbox (title update) runs the same sonar code: the same five modes, 500 ray tests per frame, the same per-point reveal memory and the same per-frame triangle budget (about 93 500) - big DLC 1 areas would be cut on the Xbox too, if that many triangles are revealed. TruXenia's Sonar page shows mode, rooms (real map or "MAP" placeholder), revealed share and the triangle counters live | ✅ static (TU); live ⬜ | ENGINE §14 "PDA sonar TU twins"; TRUXENIA.md "Sonar" |
| Sonar and loading zones | The sonar's map rooms are separate files, loaded into the sonar's own list through the same file loader the level streaming uses, and all released when the PDA closes; the streamed level rooms are not touched. Showing the other floors' rooms that the sonar loaded anyway adds no load (TruMenu "Alle verbundenen Bereiche"); loading more floors would add files to the shared loader queue | ✅ static | ENGINE §14 "PDA sonar floors, load scope" |
| Sonar look: colour, fog, cut | Every sonar map point gets the same colour (revealed cyan, unrevealed invisible); nothing on the CPU side depends on the distance. The sonar view sets the camera's far distance to 1 km and a fog whose start and end are the same distance, i.e. no usable fog - so the dimming of far rooms seen on the PC is not a normal distance fog (most likely the lighting of the sonar's map material; open). The view also cuts away everything more than 40 m in front of the point it looks at (towards the camera), so a room can vanish while the camera looks one way and appear when it turns. TruMenu 0.22.51 adds a real fog row, one-room view and a tint of the other rooms on top | ✅ static / ⬜ live | ENGINE §14 "PDA sonar view: colour, fog, cut plane, per-unit draw" |
| Sonar dimming of far rooms (solved 14.11. late) | The dimming is in the sonar map's own pixel shader, not in a fog: with the distance along the view it darkens like a light falloff down to half brightness and then fades to black over a band (the faces of the current state from about 200 to 300 m, the other face set from 500 to 600 m; values read live). Turning the fog off changed nothing (owner test 21:58). TruMenu 0.22.52 "Sonar: Abblenden Ferne" sets exactly these shader values (off / black from n/2 to n m), and "Sonar: Bereichsfarben" can give every room its own soft colour | ✅ static + live values / ⬜ live (switch) | ENGINE §17.2 "Sonar face materials" |
| Sonar loading and pause | When the PDA map opens, the game loads the map files of the rooms on the current floor plus their direct neighbours on any floor and shows the map only after all of them have arrived; closing frees them again. While the PDA is open the game is paused: the world, its loading triggers and the sounds stand still, only the file loader keeps running, and the sonar's map files are its own (no level object is involved). The "revealed" state of every map room goes into a fixed save block of about 250 KB; a room never pinged costs about 15 bytes, so even every room of the game together stays far below the limit. A whole level's map is at most 22 rooms / 16 MB / 350 000 faces (level 2); the game's own largest set is 11 MB / 250 000 faces (the DLC 1 water wheel). TruMenu 0.22.53 can load one step further or the whole connected level (with the full map); markups of the debug view then follow the sonar camera like the triggers | ✅ static + data / ⬜ live | ENGINE §14 "PDA sonar loading and extra loads", "Markup projection while the sonar is open" |
| Sonar load rule seen in the manor | Opened in the manor, the sonar also showed the secret chamber, the chamber rock hall and the chapel: the map rooms are linked by doorways (portals), not by level, and an outdoor cut-scene room came in as the "MAP" placeholder. Opened in the chapel, which is its own floor, only the chapel and its direct neighbours loaded, so the manor rooms were missing - that is the game's rule, not a fault. The view's log named four rooms whose origin lies behind its 40 m cut, which fits the cut seen in Helheim | ✅ live (owner 14.11.) + data | ENGINE §14 "PDA sonar load rule seen live" |
| Sonar room list: a new entry is half empty | When the sonar's room list meets a room name it does not know yet, the game adds an entry for it whose "file request" field is left as it was in memory - the game itself always starts the load right after, which fills that field. Something that only looks a room up without loading it leaves that leftover behind: the room then seems "already requested" (it never loads, nothing behind it is reached) and closing the sonar releases the leftover as a request and crashes (owner 15.11.: chapel -> "load everything connected" stopped after one room, then the crash on closing) | ✅ crash dump + code | ENGINE §14 "PDA sonar unit entry" |
| Help on demand | Lara's hint / answer lines (499 streams) are picked per level ("l0".."l7"). DLC 1 asks for "dlc_l1", which the PDA does not know, so DLC 1 has no help | ✅ chain / Xbox 🔶 | ENGINE §8.2 "DLC 1 help-on-demand" |
| DLC 2 PDA | DLC 2 changes the PDA main / journal page, the weapon pages (golden shotgun) and adds a DLC journal menu with DLC room names | ✅ data | Befund-DLC2-PDA-1111 |
| PDA main menu per level | Base game and DLC 1 use the "Croft VX2" device PDA with seven entries: sonar map, area info, weapon selection, inventory, help, journal (in DLC 1 "Father's Journal") and revisit location.
