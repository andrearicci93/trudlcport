# Native Direct3D 9 test

Checks whether your GPU driver and Windows' own Direct3D 9 accept every resource of the installed DLC port. It does not change the
game folder. Background and what to send back: [docs/TROUBLESHOOTING.md](../../docs/TROUBLESHOOTING.md).

Run: close the game, double-click `RUN_TEST.bat`, paste the game folder (the one with `tru.exe` and `mods`). Result: `native_report.txt`.

| File | What it does |
|---|---|
| `RUN_TEST.bat` | runs the two steps below (32-bit PowerShell, like the game) |
| `native_extract.py` | copies the shaders of your installed `mods\*.drm` into `shaders\` (`new_*` = generated by the port, `pc_*` = copied from the PC game) |
| `native_test.ps1` | creates a Direct3D 9 device on your GPU (same flags as the game: hardware VP + pure device) and calls CreatePixelShader / CreateVertexShader on every shader, CreateVertexDeclaration on `decls.json`, CreateTexture / CreateCubeTexture on `textures.json` |
| `probes\` | synthetic test shaders: lengths 511 … 32769 instructions, single features, and negative controls that must be rejected (`neg_ps_sampler_s16`) |
| `dgvoodoo\dgVoodoo.conf` | the dgVoodoo2 configuration the port was tested with (dgVoodoo itself: <http://dege.fw.hu/>, `MS\x86\D3D9.dll`) |

The top of the report shows the GPU's instruction limit (`PS30Slots`), the length probes, whether the negative controls were rejected
("BANCO VALIDO", i.e. the test is meaningful) and how many port shaders were rejected.
